# 🏢 Умный офис

Учебный проект по виртуализации, сетевым технологиям и автоматизации.

## 📌 О проекте

Цель проекта — создать виртуальный прототип сети офиса в GNS3.

В проекте реализованы:
- Сетевая инфраструктура с использованием VLAN.
- Маршрутизация между подсетями.
- Виртуальные серверы на базе РЕД ОС 8.
- Развёртывание сервисов с помощью Docker.
- Сбор показаний виртуальных датчиков температуры и влажности.
- Автоматизация и передача данных с помощью Node-RED.
- Автоматическое управление вентилятором.
- Хранение показаний датчиков и событий исполнительных устройств в базе данных SQLite.

# 📡 Практическая работа №4

## Node-RED и виртуальные датчики

### Цель

Развернуть Node-RED на IOT-01, создать виртуальные датчики и настроить автоматическую передачу показаний на CTRL-01.

### Выполненные задачи

- Запущен Node-RED через Docker Compose.
- Настроен доступ к интерфейсу через порт 1880.
- Создан виртуальный датчик температуры TEMP-01.
- Создан виртуальный датчик влажности HUM-01.
- Настроена автоматическая генерация показаний каждые 5 секунд.
- Настроена передача данных методом HTTP POST.
- Настроен приёмник данных на CTRL-01.

### Схема потока Node-RED

Inject → Change → HTTP Request

### Параметры датчиков

| Датчик | Назначение | Единица измерения |
|---|---|---|
| TEMP-01 | Температура | °C |
| HUM-01 | Влажность | % |

### Формат передачи данных

Данные передаются в формате JSON.

Пример:

json {
  "status": "ok",
  "sensor_id": "TEMP-01",
  "value": 24
}
### Проверка

- Node-RED открывается на WIN-01.
- Датчики формируют показания автоматически.
- Интервал отправки составляет 5 секунд.
- CTRL-01 получает данные от обоих датчиков.
- Передача осуществляется по HTTP POST.

### Результат

Создана система виртуальных датчиков температуры и влажности. Настроена автоматическая отправка показаний с IOT-01 на CTRL-01.

# 🌡️ Практическая работа №5

## Автоматическое управление вентилятором

### Цель

Настроить автоматическое управление вентилятором FAN-01 на основании показаний датчика температуры TEMP-01.

### Выполненные задачи

- Создан узел switch для проверки температуры.
- Настроены две ветки управления: FAN ON и FAN OFF.
- Для каждой ветки создан отдельный узел change.
- Настроено формирование команды управления вентилятором.
- Настроена передача команд методом HTTP POST.
- Настроен приём команд на сервере CTRL-01.
- Добавлены узлы Debug для просмотра ответов.

### Условия управления

| Температура | Состояние вентилятора |
|---|---|
| Выше 30 °C | ON |
| Ниже 30 °C | OFF |

### Параметры команды

| Поле | Значение |
|---|---|
| fan.actuator_id | FAN-01 |
| fan.zone | server_room |
| fan.mode | auto |
| fan.state | ON / OFF |
| fan.timestamp | Время формирования команды |

### Проверка

- При повышении температуры вентилятор получает команду ON.
- При снижении температуры вентилятор получает команду OFF.
- Команды отображаются в Debug.
- События управления сохраняются в базе данных.

### Результат

Настроена автоматическая логика управления вентилятором FAN-01 по показаниям датчика температуры TEMP-01.

# 🗄️ Практическая работа №6

## Интеграция SQLite и сохранение данных на сервере DB

### Цель

Интегрировать в систему базу данных SQLite. Настроить сохранение данных, поступающих на сервер CTRL, в базу данных, размещённую на виртуальной машине DB.

### Выполненные задачи

- Перенесены раздаточные файлы на сервер DB.
- Установлены Docker, Docker Compose и SQLite3.
- Создана база данных SQLite.
- Создана таблица measurements для хранения показаний датчиков.
- Создана таблица actuator_events для хранения событий исполнительных устройств.
- Подготовлена структура проекта для запуска через Docker Compose.
- Создана папка db для хранения базы данных.
- Настроен запуск сервиса базы данных через Docker Compose.
- Настроен HTTP-приём данных на сервере DB через порт 8081.
- Настроена передача показаний из Node-RED непосредственно на DB.

### Структура таблицы measurements

| Поле | Тип данных |
|---|---|
| id | INTEGER PRIMARY KEY |
| source | TEXT NOT NULL |
| device_id | TEXT NOT NULL |
| metric | TEXT NOT NULL |
| zone | TEXT NOT NULL |
| timestamp | INTEGER NOT NULL |
| received_at | INTEGER NOT NULL |
| value | REAL NOT NULL |
| unit | TEXT NOT NULL |
| labels | TEXT NOT NULL DEFAULT '{}' |

### Структура таблицы actuator_events

| Поле | Назначение |
|---|---|
| id | Идентификатор записи |
| source | Источник команды |
| device_id | Идентификатор устройства |
| zone | Зона размещения |
| timestamp | Время формирования команды |
| received_at | Время получения команды |
| state | Состояние устройства |
| mode | Режим работы |

### Настройка Docker Compose

Четыре раздаточных файла размещены в одной папке. В этой же папке создан подкаталог db, в котором хранится база данных SQLite с двумя таблицами.

Для запуска используется команда:

bash docker compose up -d
### Передача данных

Node-RED отправляет данные непосредственно на сервер DB по HTTP POST через порт 8081.

Используемые маршруты:

- /api/readings — приём показаний датчиков.
- /api/actuators — приём команд исполнительных устройств.

### Проверка

- Проверена работа контейнера базы данных через 
docker compose ps.
- Проверены журналы контейнера через docker compose logs.
- Проверен HTTP-адрес /health.
- Получен ответ со статусом ok.
- Проверено наличие таблиц measurements и actuator_events.
- Проверено сохранение показаний TEMP-01 и HUM-01.
- Проверено сохранение событий управления вентилятором FAN-01.
- Проверена передача данных из Node-RED на сервер DB.

### Результат

Развёрнута база данных SQLite на виртуальной машине DB. Настроен приём и сохранение показаний датчиков температуры и влажности, а также событий управления вентилятором. Данные передаются из Node-RED на сервер DB по HTTP через порт 8081.
